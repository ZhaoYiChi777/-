# 智能信息平台 Ubuntu Docker 部署说明书

本文档从“项目文件已经准备好，准备粘贴/上传到服务器”开始，说明如何在 Ubuntu 服务器上完成部署、验证，以及常见问题处理。

## 1. 部署目标

本项目建议全部基于 Docker 部署。Ubuntu 主机只需要安装 Docker Engine 和 Docker Compose 插件，不需要单独安装 Java、Maven、Node.js、Rust、MySQL、Nginx。

Docker Compose 会启动这些服务：

| 服务 | 作用 | 默认宿主机端口 |
|---|---|---|
| `frontend` | 前端页面，容器内 Nginx | `80` |
| `backend` | 后端 Spring Boot API | `8080` |
| `kg-compute` | 知识图谱计算服务 | `8101` |
| `mysql` | MySQL 数据库 | `3306` |

当前项目根目录命名建议为：

```bash
/root/back
```

项目根目录里必须能看到：

```text
docker-compose.yml
.env.example
backend-springboot
frontend-vue
kg-compute
init-db
deploy
```

## 2. 上传项目到服务器

可以通过 `scp`、SFTP、Xftp、FinalShell、MobaXterm 等工具上传。推荐上传后的目录结构如下：

```text
/root/back/docker-compose.yml
/root/back/.env.example
/root/back/backend-springboot
/root/back/frontend-vue
/root/back/kg-compute
/root/back/init-db
/root/back/deploy/deploy-ubuntu.sh
```

上传后进入服务器：

```bash
ssh root@服务器IP
```

检查项目是否完整：

```bash
cd /root/back
ls
```

如果不确定 `docker-compose.yml` 在哪里，执行：

```bash
find /root -maxdepth 5 -name docker-compose.yml -print
```

脚本运行时的项目根目录必须是包含 `docker-compose.yml` 的目录。

## 3. 第一次部署前检查

确认系统：

```bash
uname -a
cat /etc/os-release
```

当前脚本支持 Ubuntu Linux x86_64。推荐资源是 4 核 CPU、8 GiB 内存、20 GiB 以上磁盘空间。低于推荐配置也可能启动，但构建和运行会更慢，内存不足时容器可能退出。

检查端口占用：

```bash
sudo ss -ltnp | grep -E ':80|:8080|:8101|:3306'
```

默认部署需要这些端口空闲：

```text
80
8080
8101
3306
```

如果某个端口已有服务占用，先看本文档后面的“常见问题处理”。

## 4. 配置环境变量

进入项目根目录：

```bash
cd /root/back
```

如果已经有 `.env`，脚本会保留它。如果没有 `.env`，脚本会根据 `.env.example` 自动创建，并生成一个随机 MySQL root 密码。

建议部署前检查：

```bash
ls -a
nano .env
```

重点配置这些大模型相关变量：

```text
LLM_API_KEY
LLM_MODEL
LLM_PROVIDER
LLM_API_BASE_URL
EXTRACT_LLM_API_KEY
EXTRACT_LLM_MODEL
EXTRACT_LLM_PROVIDER
EXTRACT_LLM_BASE_URL
VLM_API_KEY
VLM_MODEL
VLM_PROVIDER
VLM_API_BASE_URL
EMBEDDING_API_KEY
EMBEDDING_MODEL
EMBEDDING_PROVIDER
EMBEDDING_API_BASE_URL
RERANK_API_KEY
RERANK_MODEL
RERANK_PROVIDER
RERANK_API_BASE_URL
```

如果暂时没有这些 Key，项目容器仍可能启动，但智能抽取、问答、向量检索、重排等功能可能不可用。

## 5. 运行一键部署脚本

推荐从项目根目录执行：

```bash
cd /root/back
bash deploy/deploy-ubuntu.sh
```

如果脚本不在项目根目录下，或者目录多套了一层，可以显式指定项目根目录：

```bash
bash /root/back/deploy/deploy-ubuntu.sh --project-dir /root/back
```

脚本会自动执行：

```text
1. 检查 Ubuntu / CPU / 内存 / 磁盘
2. 检查 Docker 和 Docker Compose
3. 如果 Docker 不存在，从阿里云 Docker CE 源安装 Docker
4. 检查 .env 和 docker-compose.yml
5. 检查端口 80 / 8080 / 8101 / 3306
6. 构建并启动容器
7. 检查后端健康接口
8. 检查前端页面是否可访问
```

如果只想检查环境，不启动服务：

```bash
bash deploy/deploy-ubuntu.sh --no-start
```

如果 Docker 已经安装好，不希望脚本再安装 Docker：

```bash
bash deploy/deploy-ubuntu.sh --skip-install
```

如果只想启动现有镜像，不重新构建：

```bash
bash deploy/deploy-ubuntu.sh --skip-build
```

如果需要强制重建并重建容器：

```bash
bash deploy/deploy-ubuntu.sh --force-rebuild
```

## 6. 部署成功后的验证

查看容器状态：

```bash
cd /root/back
docker compose ps
```

如果当前用户还没有 Docker 权限，用：

```bash
sudo docker compose ps
```

检查后端健康接口：

```bash
curl http://127.0.0.1:8080/api/health
```

浏览器访问前端：

```text
http://服务器IP/
```

如果修改了前端宿主机端口，比如改成 `8088`，访问：

```text
http://服务器IP:8088/
```

查看日志：

```bash
docker compose logs --tail 100 backend
docker compose logs --tail 100 frontend
docker compose logs --tail 100 mysql
docker compose logs --tail 100 kg-compute
```

持续跟踪日志：

```bash
docker compose logs -f backend
```

## 7. 常见问题处理

### 7.1 找不到 docker-compose.yml

报错示例：

```text
[ERROR] docker-compose.yml was not found in /root/back
```

处理方式：

```bash
find /root -maxdepth 5 -name docker-compose.yml -print
```

找到后，使用包含 `docker-compose.yml` 的目录作为项目根目录：

```bash
bash /root/back/deploy/deploy-ubuntu.sh --project-dir /实际项目根目录
```

如果 `find` 没有输出，说明服务器上没有上传完整项目，只上传了脚本或部分文件。需要重新上传完整项目目录。

### 7.2 80 端口被占用

报错示例：

```text
[ERROR] Required host port 80 is already in use.
```

查看占用进程：

```bash
sudo ss -ltnp | grep ':80'
```

如果是无关服务，可以停止它，例如：

```bash
sudo systemctl stop nginx
sudo systemctl disable nginx
```

如果不能停止原服务，可以修改 `docker-compose.yml`，把前端宿主机端口改成其他端口：

```yaml
ports:
  - "8088:80"
```

然后把脚本里的端口检查也从 `80` 改成 `8088`，或者临时手动启动：

```bash
docker compose up -d --build
```

访问地址改为：

```text
http://服务器IP:8088/
```

### 7.3 8080 / 8101 / 3306 端口被占用

检查占用：

```bash
sudo ss -ltnp | grep -E ':8080|:8101|:3306'
```

处理方式有两种：

```text
1. 停掉占用端口的旧服务
2. 修改 docker-compose.yml 的宿主机端口映射
```

例如后端改成宿主机 `18080`：

```yaml
ports:
  - "18080:8080"
```

注意：容器内部端口通常不要改，只改冒号左边的宿主机端口。

### 7.4 Docker 安装成功但 docker 命令没权限

提示示例：

```text
This run uses sudo. Re-login before using Docker without sudo.
```

这是正常提示。脚本已经把当前用户加入 `docker` 组，但需要重新登录才生效。

当前会话可以先用：

```bash
sudo docker compose ps
```

重新登录服务器后再用：

```bash
docker compose ps
```

### 7.5 Docker 拉取镜像很慢或失败

脚本安装 Docker 使用的是阿里云 Docker CE APT 源，但项目镜像构建时仍可能访问 Docker Hub、npm、Maven、Cargo 等依赖源。

可以重试：

```bash
docker compose build --no-cache
docker compose up -d
```

如果网络环境限制严重，需要配置 Docker 镜像加速器，或提前在可联网环境构建镜像后导出再导入服务器。

### 7.6 构建时提示 node_modules 不存在

这是正常的。当前项目已经删除了本地 `frontend-vue/node_modules`，Docker 构建会在镜像内部重新安装依赖。

如果构建失败，重点看前端 Dockerfile 和 npm registry 网络访问。

### 7.7 构建时提示 backend-springboot/target 不存在

这也是正常的。当前项目已经删除了本地 Maven 构建产物 `target`，Docker 构建会在镜像内部重新打包。

如果构建失败，重点看 Maven 依赖下载网络、后端 Dockerfile 和 `pom.xml`。

### 7.8 后端健康检查失败

脚本可能输出：

```text
Backend did not become healthy within five minutes.
```

查看后端日志：

```bash
docker compose logs --tail 200 backend
```

常见原因：

```text
1. MySQL 没有启动成功
2. .env 里的 MySQL 密码和容器环境不一致
3. 后端构建失败或启动异常
4. 内存太小，Java 进程启动慢或被系统杀掉
5. 大模型配置缺失导致某些初始化逻辑失败
```

继续查看 MySQL：

```bash
docker compose logs --tail 200 mysql
docker compose ps
```

### 7.9 前端健康检查失败

查看前端日志：

```bash
docker compose logs --tail 200 frontend
```

确认前端端口：

```bash
docker compose ps
curl -I http://127.0.0.1/
```

如果改过前端端口，例如 `8088:80`：

```bash
curl -I http://127.0.0.1:8088/
```

### 7.10 内存或 CPU 不足

脚本可能提示：

```text
[WARN] CPU cores: 2 (recommended: 4 or more)
[WARN] Memory (GiB): 3.4 (recommended: 8 or more)
```

这是警告，不一定会阻止部署。但低配置环境下，构建速度会慢，后端 Java 容器更容易因内存不足启动失败。

可以尝试：

```bash
docker compose up -d --build
docker compose logs -f backend
```

如果频繁失败，建议增加服务器内存，或降低 `docker-compose.yml` 中后端的 `JAVA_OPTS`。

### 7.11 防火墙或云安全组无法访问

服务器本机能访问，但外部浏览器打不开时，检查防火墙：

```bash
sudo ufw status
```

放行前端端口：

```bash
sudo ufw allow 80/tcp
```

如果前端改成 `8088`：

```bash
sudo ufw allow 8088/tcp
```

云服务器还要在云厂商控制台安全组里放行对应端口。

## 8. 常用运维命令

进入项目根目录：

```bash
cd /root/back
```

启动：

```bash
docker compose up -d
```

重新构建并启动：

```bash
docker compose up -d --build
```

停止：

```bash
docker compose down
```

停止并删除数据卷：

```bash
docker compose down -v
```

注意：`docker compose down -v` 会删除 MySQL 数据卷和后端上传/数据卷，除非明确要清空数据，否则不要执行。

查看状态：

```bash
docker compose ps
```

查看日志：

```bash
docker compose logs --tail 100
```

查看磁盘占用：

```bash
docker system df
```

清理未使用镜像和构建缓存：

```bash
docker system prune
```

## 9. 离线部署预案

如果目标服务器无法访问 Docker Hub、Maven、npm、crates.io，需要提前在一台可联网机器上制作离线镜像包。

离线包工具目录：

```bash
deploy/offline-package
```

在可联网机器上执行：

```bash
cd /root/back
bash deploy/offline-package/prepare-offline-package.sh
```

生成的离线包默认在：

```text
deploy/offline-package/dist/intelligence-platform-offline-时间戳
```

把整个生成目录传到目标服务器后执行：

```bash
cd /root/intelligence-platform-offline-时间戳
bash load-offline-package.sh --project-dir /root/back
```

注意：离线包解决的是项目镜像和构建依赖问题，目标服务器仍需要提前安装 Docker Engine 和 Docker Compose 插件。

详细说明见：

```text
deploy/offline-package/README.md
```

## 10. 最终完成标准

满足以下条件即可认为部署完成：

```text
1. docker compose ps 显示主要服务处于 running / healthy 状态
2. curl http://127.0.0.1:8080/api/health 成功
3. 浏览器可以打开 http://服务器IP/
4. .env 中真实 API Key 已配置
5. 服务器防火墙或云安全组已放行前端访问端口
6. 业务页面可以完成一次基本功能验证
```

高级文档解析相关的 `parser-service` 目前没有纳入 `docker-compose.yml`，所以 MinerU、Marker、PaddleOCR 等高级解析能力不属于本脚本的一键部署范围。
